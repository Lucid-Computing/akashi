# Glossary

## Terms

| Term | Meaning |
|---|---|
| Holder | Party possessing the original transcript and its verification material |
| Transcript | Prompt and reply token sequences under a render profile and resolved request budget |
| Render profile | Versioned mapping between holder input, token IDs and displayed reply text |
| Receipt | Signed promise binding a transcript commitment and delivery metadata |
| Signed tree head | Signed checkpoint of a particular log size and root |
| Selection gap | A sample obligation whose selection or evidence could not be completed |
| Escrow | Temporary custody of a transcript while awaiting selection |
| Pickup | Recovery of a sealed verification envelope using holder transcript material |
| Conformance | Exact greedy agreement over every served reply position |
| Deviation | A proven difference at a stated position under the committed model |
| Incomplete | A reply that violates the budget or end-token completeness rule |
| Excused range | A range limitation whose evidence supports classification outside the served positions |
| Unavailable | Audit lacks sufficient verifiable evidence for conformance, deviation or other accountable outcome |
| Mode D | Direct holder-to-gateway delivery |
| Mode R | Delivery via an inference router |

See [source glossary](../../specs/glossary.md#terms) for component abbreviations and parameter symbols.
